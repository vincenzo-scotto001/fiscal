# Fiscal bot: working notes

- **Never push to `main`.** Make every change on a new branch and open a pull request for the owner to review and merge.
- Run `python tests/test_offline.py` and `python tests/test_feeds_offline.py` before opening a PR. They run every post type against sample data and check Discord's message limits.
- Economic releases are matched by exact FRED release name (`KEY_RELEASES` in `fiscal_bot.py`). After changing them, ask the owner to run the `check` task from the Actions tab and confirm the matches in the log.
- The bot posts to a live Discord server. For manual test runs, use `--dry-run` (or the workflow's dry-run box).
- Media sources (videos, podcasts, news, research) live in `sources.yml`. After changing them, ask the owner to run the `check-feeds` task from the Actions tab.
- Schedules: `cron` lines are in **UTC with no `timezone:` key** (GitHub ignored it on this repo, and scheduled runs arrive late or get skipped). Each fiscal post has a cron chance every 15 minutes inside its window; `fiscal_bot.py` posts only inside `AUTO_WINDOWS` and remembers what it posted today (`.state/fiscal.json`, kept in the Actions cache). `feeds_bot.py` runs every 15 minutes with quiet hours. This many runs is only free because the repo is public. The schedule replay in `tests/test_offline.py` must still pass after any cron change.
\n- The **Fiscal ticker** (`.github/workflows/ticker.yml`) is what actually keeps posts on time: each tick dispatches `fiscal.yml` and `feeds.yml` with `task: auto` and queues the next tick, which waits 30 minutes in the `ticker-30m` environment (wait timer; public repos only). Keep `auto` in both workflows' Run-workflow options, and keep the bots' daily memory: the ticker, the cron backups and manual runs can all overlap.\n
