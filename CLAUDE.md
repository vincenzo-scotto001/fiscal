# Fiscal bot: working notes

- **Never push to `main`.** Make every change on a new branch and open a pull request for the owner to review and merge.
- Run `python tests/test_offline.py`, `python tests/test_feeds_offline.py`, `python tests/test_analysis_offline.py` and (from `trade_bot/`) `node --test` before opening a PR. They run every post type against sample data and check Discord's message limits.
- Economic releases are matched by exact FRED release name (`KEY_RELEASES` in `fiscal_bot.py`). After changing them, ask the owner to run the `check` task from the Actions tab and confirm the matches in the log.
- The bot posts to a live Discord server. For manual test runs, use `--dry-run` (or the workflow's dry-run box).
- Media sources (videos, podcasts, news, research) live in `sources.yml`. After changing them, ask the owner to run the `check-feeds` task from the Actions tab.
- Schedules: `cron` lines are in **UTC with no `timezone:` key** (GitHub ignored it on this repo, and scheduled runs arrive late or get skipped). Each fiscal post has a cron chance every 15 minutes inside its window; `fiscal_bot.py` posts only inside `AUTO_WINDOWS` and remembers what it posted today (`.state/fiscal.json`, kept in the Actions cache). `feeds_bot.py` runs every 15 minutes with quiet hours. This many runs is only free because the repo is public. The schedule replay in `tests/test_offline.py` must still pass after any cron change.

- The **Fiscal ticker** (`.github/workflows/ticker.yml`) is what actually keeps posts on time: each tick dispatches `fiscal.yml`, `feeds.yml` and `analysis.yml` with `task: auto` and queues the next tick, which waits 30 minutes in the `ticker-30m` environment (wait timer; public repos only). Keep `auto` in the three workflows' Run-workflow options (fiscal, feeds, analysis), and keep the bots' daily memory: the ticker, the cron backups and manual runs can all overlap.
- **Trade alerts** (`trade_bot/`): Discord slash commands on a Cloudflare Worker, deployed by `.github/workflows/deploy-trade-bot.yml` on merge. Hard rule from the owner: cards show only what was bought or sold, the prices in and out, and the % result. **Never position size, share count or contract count** (a test enforces this), and no trade numbers (removed at the owner's request; positions keep an internal id, and lists show the day opened). Open positions live in Cloudflare KV, never in the repo. IDs are GitHub *variables*; tokens are *secrets*.
- **Fiscal AI** (`trade_bot/src/ai.js`): `/ask-fiscal` and `/bull-bear` are for every member, and the trade commands stay owner-only. They run on OpenAI's Responses API (`gpt-6.2-sol`, reasoning effort `low`, which is the lowest the model accepts) with the owner's key. Rules to keep: explain, never advise (no buy/sell calls, price targets, predictions or position sizes); finance only; the model gets live data first (Finnhub, FRED, CoinGecko) and may only use numbers from it; footers say "AI-generated · Not financial advice". Bull/bear cards have exactly 3 + 3 points with no verdict. Limits: 3 questions + 3 bull/bears per member per day (midnight ET), unlimited for the owner and `PREMIUM_ROLE_ID`, plus the server-wide `AI_DAILY_CAP`. Background work must finish within Cloudflare's 30 seconds after the reply, so keep the OpenAI and data timeouts short. Never log keys.
- **Fiscal analysis** (`analysis_bot.py`, `.github/workflows/analysis.yml`): #analysis posts in the owner's house style. IMG 1 is the daily technical chart and IMG 2 is options positioning (gamma and OI by strike from Cboe's delayed chains). Mondays at 8:37 AM ET for SPX and NDX via `auto`; `/analysis TICKER` comes from the Worker (`trade_bot/src/analysis.js`), which posts a placeholder and starts the workflow with `task: request` using the `GH_DISPATCH_TOKEN` secret. Owner's rules, enforced in code (`RULES`, `unverified_numbers`): levels and if/then scenarios only, targets only as named technical levels from DATA, no "PT"/price targets, no firm predictions, no buy/sell calls, no first-person trades, no @here. All numbers are computed before the model sees them. The JPM collar is entered by the owner with `/collar` and stored in KV. Chart colors were checked with the dataviz validator for colorblind safety. After changing data sources, ask the owner to run `check-analysis` from the Actions tab.
- **Alerts** (`trade_bot/src/alerts.js`): `/alert price|earnings|list|remove` for every member, DM'd (with a ping in the alert's channel as a fallback). One KV key (`alerts`) holds them all. The Worker's cron trigger (`[triggers]` in the generated wrangler.toml, every 5 minutes 13:00-21:55 UTC) runs `runAlerts`, which handles market hours, weekends and Finnhub's market status itself. Stay under the free plan's 50 outside requests per run (`MAX_TICKERS_PER_RUN`, `MAX_NOTICES_PER_RUN`). Limits: 5 alerts per member, 25 for the owner and Premium.
